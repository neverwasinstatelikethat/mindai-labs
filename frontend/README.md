# Клиентская часть — `frontend/`

Клиентское SPA-приложение платформы «Научный Клубок»: SvelteKit 2 + Svelte 5 + Tailwind CSS 4. Предоставляет исследовательское рабочее пространство, визуализацию графа знаний, сравнение сущностей, дашборд, аккаунт и доступ.

## Страницы и маршруты

### Главная (`/`)

**Файл:** `+page.svelte` (68 строк)

Продуктовая лендинг-страница. Содержит:
- Героический блок с описанием платформы и призывом к действию
- Пример проверяемого ответа с условиями, цитатой и ссылкой на источник
- Описание трёхшагового процесса (добавить материалы → система сопоставит → проверить результат)
- Блок «Доказательность по умолчанию»: три уровня доверия (извлечено / выведено моделью / проверено экспертом)

### Рабочее пространство (`/research`)

**Файл:** `research/+page.svelte` (497 строк)

Основная рабочая страница исследователя. Содержит 5 вкладок (некоторые доступны по ролям):

| Вкладка | Доступность | Назначение |
|---|---|---|
| **Запросы** | Все роли | Чат с агентом: ввод вопроса, отображение ответа (краткое содержание, утверждения, доказательства, конфликты, пробелы, рекомендации), план запроса, трассировка агентов |
| **Карта связей** | Все роли | Интерактивная визуализация графа с выбранным узлом и информацией о связях |
| **Проверка** | Руководитель проекта+ | Проверка эволюционных предложений (принять/отклонить), запуск A/B-экспериментов, проверка слияний сущностей |
| **Импорт** | Все роли | Загрузка документов (PDF/DOCX/XLSX/JSON), статистика корпуса, история версий утверждений |
| **Оценка** | Аналитик+ | Эталонные случаи, запуск бенчмарка поиска и сквозного бенчмарка, просмотр метрик |

**Возможности вкладки «Запросы»:**
- Отображение намерения запроса с классификацией (поиск фактов, обзор литературы, сравнение технологий и т.д.)
- Список утверждений с доказательствами: источник, страница, цитата, уверенность
- Числовые наблюдения с форматированием (диапазоны, операторы сравнения)
- Конфликты и пробелы в знаниях
- Трассировка агентов с временем выполнения каждого шага
- Экспорт ответа в Markdown (для аналитиков и выше)
- История версий утверждений (при экспертной корректировке)

### Граф знаний (`/graph`)

**Файл:** `graph/+page.svelte`

Полноэкранная интерактивная карта графа знаний:
- Визуализация узлов (сущности, утверждения, процессы) и рёбер (связи между ними)
- Масштабирование и перемещение по холсту
- Расширение соседей выбранного узла
- Подсветка путей между узлами
- Фильтрация по типам узлов
- Отображение сообществ графа

### Находки (`/findings`)

**Файл:** `findings/+page.svelte`

Список всех утверждений (находок) в базе знаний:
- Полная формулировка утверждения
- Статус (подтверждено / оспорено / гипотеза)
- Уверенность и версия
- Доказательства с цитатами и ссылками на источники
- Числовые наблюдения
- Область применения (scope)

### Сравнение (`/compare`)

**Файл:** `compare/+page.svelte` (237 строк)

Сравнительный анализ сущностей по числовым свойствам:
- Ввод вопроса и списка сущностей для сравнения (через «чипы»)
- Необязательные размеры (свойства) для фильтрации столбцов
- Результат — таблица, где строки — сущности, столбцы — свойства
- Каждая ячейка содержит значение, единицу измерения, уверенность и цитату-доказательство
- Поддержка URL-параметров для предзаполнения (`?q=...&entities=...`)
- Доступ: аналитик и выше

### Обратная связь (`/feedback`)

**Файл:** `feedback/+page.svelte`

Панель экспертной обратной связи по утверждениям:
- Список последних запросов и их утверждений
- Три вердикта: принять / отклонить / исправить
- Поле комментария и необязательное исправление формулировки
- Отправка создаёт предложение эволюции (EvolutionProposal)

### Панель состояния (`/dashboard`)

**Файл:** `dashboard/+page.svelte`

Сводная панель состояния системы, разделы:

- «Документы, утверждения и доказательства» — карточки корпуса и состав;
- «Покрытие и его знаменатели» — цитаты, числовая поддержка, доля тезисов без
  поддержки, противоречия и пробелы;
- «Проходы агентов» — метрики агентного контура и вызовов модели (вызовы, сбои,
  повторы, средняя и p95 задержка);
- журнал последних актов — свои события аккаунта, а держателю права
  `audit:read` — последние акты контура со столбцом «аккаунт»;
- «Прогоны оценки» — читаются только при праве на просмотр оценок.

Доступ: любой подтверждённый аккаунт (права приходят с `/api/v1/auth/me`);
отдельной «роли администратора» в продукте нет. Часть показаний может не
читаться — тогда раздел говорит об этом отдельно, а не рисует ноль.

## Библиотечные модули

### `api.ts` (148 строк)

HTTP-клиент для серверного API. Обёртка над `fetch()` с `credentials: "same-origin"` (сессия — httpOnly cookie `nk_session`, клиент её не читает и никуда не вставляет), разбором ошибок и обработчиком `401`. Ролевых заголовков в продукте нет.

**Методы:**

| Категория | Методы |
|---|---|
| **Система** | `status()`, `agentMetrics()` |
| **Запросы** | `query(question)`, `demo()`, `validateQuery(plan)` |
| **Граф** | `graph()`, `corpusStats()` |
| **Импорт** | `upload(file)` |
| **Обратная связь** | `feedback(queryId, findingId, verdict, comment)` |
| **Эволюция** | `proposals()`, `experiments()`, `runExperiment(id)`, `review(id, accepted)` |
| **Слияние** | `mergeProposals()`, `reviewMerge(id, action)` |
| **Оценка** | `evaluations()`, `goldCases()`, `retrievalBenchmark()`, `pipelineBenchmark()` |
| **Журнал аудита и решения** | `audit()`, `decisions()` |
| **Сессия и аккаунт** | `me()`, `register()`, `login()`, `logout()`, `updateProfile()`, `changePassword()` |
| **Сравнение** | `compare(question, entities, dimensions)` |
| **Экспорт** | `export(queryId, format)` — сервер перечитывает свою копию ответа по `query_id`, содержимое клиент не передаёт |
| **История** | `claimHistory(claimId)` |
| **Панель** | `dashboard()` |

Базовый URL читается из переменной окружения `PUBLIC_API_URL`, по умолчанию `/backend` (через прокси SvelteKit).

### `ui/NavBar.svelte` и `rail.ts`

Единая навигация для группы `(app)` (пришла на смену удалённой `AppHeader.svelte`):

- **Разделы** описаны в `rail.ts` и отрисованы `NavBar`; экспертные пункты
  скрываются по `capabilities` из `/auth/me`, но решение всегда за сервером
- **Лента уведомлений** — колокольчик читает `/api/v1/notifications` опросом;
  подписка фиксирует интерес к теме и не обещает рассылку
- **Состояние системы** и ссылка аккаунта (`/account`) с правами текущей сессии
- **Переключателя ролей нет**: выбор роли был удалён из продукта вместе с
  заголовками `X-User-Role`

### `ChatPanel.svelte` (~57 КБ)

Основной компонент чата для взаимодействия с агентом:
- Поле ввода вопроса с поддержкой Enter
- Отображение загруженного состояния (анимация ожидания)
- Рендеринг полного ответа: краткое содержание, намерение, план запроса, находки, доказательства, наблюдения, конфликты, пробелы, рекомендации
- Трассировка агентов с временными метками
- Форматирование числовых наблюдений
- Отображение метрик оценки (покрытие цитирования, числовая поддержка, точность)

### `GraphCanvas.svelte` (~31 КБ)

Визуализация графа знаний на HTML-холсте (Canvas API):
- Отрисовка узлов с цветами по типам (материал, процесс, оборудование, условие, утверждение, эксперимент, публикация, эксперт)
- Отрисовка рёбер с подписями типов связей
- Масштабирование колесом мыши
- Перемещение перетаскиванием
- Выделение узла по клику с отображением метаданных
- Расширение соседей: при клике на узел подгружаются связанные сущности
- Подсветка пути между выбранными узлами
- Фильтрация по типам узлов (чекбоксы)
- Адаптивный размер холста

### `sessionStore.svelte.ts`

Реактивное хранилище подтверждённой сессии (заменило удалённый `roleStore`):

- Состояния `unknown` / `anonymous` / `authenticated`; аккаунт приходит с `/auth/me`,
  потому что `nk_session` — httpOnly и клиент его не читает
- `setUnauthorizedHandler`: ответ `401` от любого запроса возвращает сессию в
  `anonymous` и уводит на `/login`
- Правок доступа на клиенте нет: есть `capabilities` из ответа сервера, и они
  только скрывают элементы — решение всегда за сервером

### `types.ts`

Полный набор TypeScript-типов, зеркально отражающих серверные контракты (`contracts.py`, `models.py`, `intelligence.py`). Включает:

- Все модели данных (Finding, GraphSnapshot, AnswerPayload и т.д.)
- Типы аккаунта и доступа (`AccountInfo`, `Capability`, `DataClass`)
- Справочник `CAPABILITY_LABELS` — русские названия прав для интерфейса
- Ролей и `hasPermission(role, permission)` в клиенте больше нет: проверка прав на
  сервере, в UI только признаки из `/auth/me`

## Доступ на клиенте

1. Раскладка `(app)` при старте вызывает `refresh()` → `/auth/me`; без сессии —
   редирект на `/login` с возвратом на исходный маршрут
2. Регистрация и вход идут теми же эндпоинтами, что и браузер в реальном контуре;
   токен не хранится в `localStorage`, cookie ставит сервер
3. Элементы экспертного контура (`proposal:review`, `audit:read`, `restricted:read`)
   скрываются по `account.capabilities`, но запрос без права всё равно получает `403`
4. Переключателя ролей в интерфейсе нет и быть не может: выдача экспертных прав —
   признак аккаунта `review_enabled`, который добавляет администратор

### Фильтрация интерфейса

| Элемент | Условие показа |
|---|---|
| Обзор предложений, журнал аудита, ограниченные данные | capability из `/api/v1/auth/me` |
| Экспорт ответа | подтверждённая сессия + право `export:run` |
| Сравнение, дашборд, находки, граф | подтверждённая сессия |

## Взаимодействие с сервером

### Проксирование запросов

В режиме разработки SvelteKit проксирует запросы к `/backend/*` на серверную часть. В промышленном развёртывании используется Nginx или аналогичный обратный прокси.

### Обработка ошибок

Все API-вызовы оборачиваются в `try/catch`. При ошибке:
- Отображается карточка ошибки с понятным пользователю сообщением
- Для HTTP 403 — подсказка о недостаточных правах
- Для HTTP 503 — подсказка о недоступности LLM
- Для сетевых ошибок — подсказка о необходимости запустить серверную часть

## Сборка и запуск

### Разработка

```bash
cd frontend
npm ci          # Установка зависимостей
npm run dev     # Сервер разработки (http://localhost:5173)
```

### Проверка типов

```bash
npm run check   # svelte-check с TypeScript
```

### Сборка для развёртывания

```bash
npm run build   # Vite build → Node.js-приложение
npm run preview # Предпросмотр собранного приложения
```

### Docker

```bash
docker build -t mindai-frontend .
docker run -p 43119:3000 mindai-frontend
```

`Dockerfile` использует `@sveltejs/adapter-node` для запуска как Node.js-сервер (не статический сайт), что позволяет проксировать запросы к серверной части.
